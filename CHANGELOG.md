# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **A workflow parked in its recoverable failure state now offers the same retry to a continued session as to the process that failed.** The retry replayed the last classified Boss event, which lives in process memory and is deliberately absent from the durable snapshot, so `playbook run --continue` — and any reopening by session id — restored a parked failure with no actions at all, leaving the Captain able only to dismiss and restart it. The same gate withheld the retry inside the live process whenever the last Boss boundary was a reply that resumed work which then failed, because a failure state accepts only its entry event. A workflow artifact now names the FSM context member its entry action copies the exact Boss text into, and the retry is built from that member of the live snapshot, which the persisted machine snapshot already carries; CODE and REVIEW both declare it. Nothing new is persisted, so the runtime snapshot, its schema, and every written record are unchanged, and an artifact that declares no member keeps its previous process-local behavior ([DR-034](specs/decisions/034-durable-failure-retry-continuity.md), [IR-044](specs/intents/044-durable-failure-retry-continuity.md), [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)]).

### Fixed

- **Terminal completion now retains its authored outcome meaning even when a runtime exposes no control actions.** DECIDE already reached distinct approval-backed and REVIEW-failure final states, but its intentionally pair-less runtime gave the shell no `describe()` channel before disposal, so both outcomes were reported as having no published description. The terminal `PlaybookRunResult` now carries the exact authored final-state description when one exists; the shared factory and DECIDE publish it, and the shell prefers it while retaining the live-view and honest-absence fallbacks for older runtimes. Opaque machine output remains runtime-to-runtime data and is never repurposed as Boss-facing evidence ([DR-037](specs/decisions/037-terminal-result-meaning.md), [[playbook-runtime-41](specs/packages/playbook-runtime.md#playbook-runtime-41)], [[playbook-captain-20](specs/packages/playbook-captain.md#playbook-captain-20)]).

- **A distinct failure racing a turn abort is no longer misreported as a clean cancellation.** The engine classified any `AbortError`-named rejection — and, on the player path, any rejection at all — as the abort whenever the turn signal was aborted, demoting real transport and adjudication faults to trace payloads while the Boss saw a clean abort. Every boundary now classifies by exact identity with the combined signal's reason, the rule [slc/link.md](slc/link.md) has stated since release and DECIDE's bespoke runtime already implemented ([[playbook-runtime-13](specs/packages/playbook-runtime.md#playbook-runtime-13)]). The same identity rule now governs the reverse direction on the emission, drain, and settlement channels — in the shared engine and in DECIDE — so a trace sink whose rejection is the cancelled turn's own abort reason no longer turns a clean cancellation into a control-plane rejection.

- **Abort settlement now follows one recorded model.** [DR-036](specs/decisions/036-coherent-abort-settlement.md) fixes the design the preceding hardening converged on piecemeal, and this release completes its implementation across the shared engine and DECIDE. Classification moved into every latch and report site — the shared start helper, the nested bridge's start, finish, drain, background, and cleanup paths, and the apply delivery latch — so an exact cancellation is consumed in its own phase instead of being relabeled as a control failure. Before a host call or effect begins it prevents that work, pairs a recorded start with an `aborted` finish, and makes an ordinary run settle `aborted`; pre-acceptance apply instead rejects the exact reason and records no receipt. A previously recorded finish is never contradicted; after apply acceptance a pre-publication failure folds into the `failed` receipt, while an exact rejection after a non-apply outcome or published receipt is dropped without rewriting that fact or poisoning a later boundary. Settlement gained one precedence order: a machine that completes to its terminal state reports `terminal` with its output even when the signal also aborted, where it previously hid behind an `aborted` settlement that the next turn silently restarted — duplicating the workflow's side effects. A `resumePlaybookCall` whose signal is already aborted now delivers nothing and preserves the pending call for a later resume, where it previously consumed the child result, moved the machine to terminal, and reported `aborted` over it. During a resume the bridge preserves both cancellation provenances — its invocation-lifetime combined signal and the resume boundary's own signal — instead of reducing later classification to whichever mutable signal remains active ([[playbook-runtime-13](specs/packages/playbook-runtime.md#playbook-runtime-13)], [[playbook-runtime-42](specs/packages/playbook-runtime.md#playbook-runtime-42)]).

- **A startup actor failure now fails `init` instead of vanishing.** An initial entry action that threw left `init` resolving over a dead machine — `session.started` emitted with no disposal, empty turns reporting `no-action` over an errored actor, and the error latch silently reset by the next boundary. A startup actor error now rides the emission channel `init` and `restore` drain, so the boundary rejects with the original error after the failed-start cleanup and a fresh `init` remains permitted; a settlement-view defect can also no longer wedge later boundaries behind "another runtime turn is active", because every public boundary now releases its sentinel in a `finally` ([[playbook-runtime-37](specs/packages/playbook-runtime.md#playbook-runtime-37)]).

- **A state without a description is usable, as the contract always said.** Snapshot normalization demanded a nonempty `meta.playbook.description` for every active state, so a spec-legal descriptionless state failed its first activation — and, through the settlement wedge above, permanently locked the runtime. Normalization now treats the description as the optional member the published contract declares, omitting `stateDescription` downstream ([[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)]).

- **A synchronous FSM action failure no longer escapes as an unobserved actor error.** An action or guard that threw before the turn's quiescence wait subscribed left the root actor's error unobserved, so the failure surfaced as an `uncaughtException` after the public method returned — fatal in a default Node host — and, when it coincided with an abort, the method also resolved a falsified clean `aborted` result that omitted the failure. The runtime now observes the root actor's errors, latches any that are not the abort reason itself as the turn's control-plane error, and settles an errored actor ahead of a coincident abort ([[playbook-runtime-13](specs/packages/playbook-runtime.md#playbook-runtime-13)]).

- **A player start recorded by a rejecting trace sink now finishes its pair.** Every other call boundary already emitted the mandated best-effort `error` finish when its started-trace sink recorded the event and then rejected; the normal player path alone left a permanently unpaired `player.call.started`, presenting a forever-in-flight call to any trace consumer. The player start now routes through the same pairing helper as the judge, Captain, and apply boundaries: no host call begins, the pair finishes `error` preserving the call id and prompt, and the method rejects with the original sink error ([[playbook-runtime-37](specs/packages/playbook-runtime.md#playbook-runtime-37)]).

- **An aborted script now dies with its whole process group before the turn settles.** The script actor sent one `SIGTERM` to the wrapper shell and settled immediately, so the runtime reported quiescence while `TERM`-immune commands and backgrounded descendants kept mutating the workspace — and a Boss retry could race the orphan. The shell now runs detached as its own process group; abort terminates the group, escalates to `SIGKILL` after a bounded grace, and reports clean cancellation only after the shell exits and an `ESRCH` probe confirms that the group stopped being signalable — a shell that exits cooperatively on the group `SIGTERM` no longer strands a `TERM`-immune descendant, and settlement no longer races the kernel's teardown of a just-killed member. A bounded confirmation failure surfaces distinctly instead of claiming cleanup succeeded. Abort ownership now spans the whole invocation: an abort landing during the post-exit status and telemetry tail still kills whatever group members outlived the shell, then rejects before the guard resolves, so a completed-but-aborted script never records a terminal machine behind an `aborted` settlement or reports clean cancellation while a survivor remains unconfirmed ([DR-036](specs/decisions/036-coherent-abort-settlement.md), [slc/link.md](slc/link.md)).

- **The shared factory rejects machines outside its flat domain at construction.** A non-parallel compound machine — a state whose `meta.playbook.stateId` differs from its key, or declares none at all, or a machine declaring no root states — was accepted and then misbehaved only later: silently dead state-keyed gates for the split identity, and a misnamed first-snapshot failure at `init` for the missing identity and the zero-state machine. All four shapes now fail construction with named diagnostics, beside the existing parallel rejection ([[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)]).

- **Shipped documentation resolves, with its two escape hatches verified.** The published tarball carried 33 relative links into unshipped `specs/`, `CHANGELOG.md`, and test files, plus two malformed SLC reference definitions; repository-only targets now cite absolute repository URLs, the definitions are repaired, the embedding guide names `p-queue` as the host's own dependency, the external-registry guide scopes `.ts` loading to Nodes with native type stripping, and a recursive packed-closure test guards the whole class. The closure has two deliberate exceptions — living `blob/main` or `tree/main` repository URLs and a packed SLC definition's meta-16 relative citations into `specs/` — and both are now verified rather than waved through: every living-pointer URL must name this repository's `main` with an existing path and anchor, and every exempted citation's target and anchor must exist in the repository tree ([[release-20](specs/packages/release.md#release-20)]).

- **A workflow that fails after an answered Boss question now settles durably instead of voiding the turn.** Both maintained workflows retain the answered question in FSM context so the resumed player prompt can quote it, and the exported runtime snapshot projected that member unconditionally — while state telemetry gates it on the Boss-reply wait. A failure reached after the reply therefore exported a "pending" question the shell's telemetry-fed mirror had already cleared, the required mirror/snapshot equality failed, and the turn died at settlement: exit 2, the reply withheld, progress discarded to the uncertain baseline — in both front ends. The snapshot, the control view, and the classifier prompt now count a question as pending only while the machine sits in the Boss-reply wait, one shared gate with the telemetry, so the parked failure settles, the judge is no longer shown an answered question as awaiting, and the DR-034 retry recovers the run across `playbook run --continue` ([[playbook-runtime-45](specs/packages/playbook-runtime.md#playbook-runtime-45)], [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)]).

- **Delivered text at a workflow's recoverable failure state now restarts it deterministically.** [[playbook-runtime-1](specs/packages/playbook-runtime.md#playbook-runtime-1)] has always named the failure state a deterministic entry beside idle and terminal, but the shared engine classified there, spending a judge call that could settle the restart as no action; the engine now routes `failed` deterministically like DECIDE's bespoke runtime always did, so a delivered fresh intent restarts without a judge in the loop.

- **DECIDE reports a question as pending only while its authored wait is active.** Its bespoke telemetry and snapshot projected every contextual question, so an answered branch or commit question stayed observably pending through the resumed player call, and both parallel branch questions were reported after only one remained; both surfaces now filter through the active authored wait states across all three reply paths ([[playbook-runtime-45](specs/packages/playbook-runtime.md#playbook-runtime-45)]).

- **Artifact compatibility declarations are now link-time literals.** The bundled CODE, REVIEW, and Captain artifacts imported the loading engine's `RUNTIME_ABI` into `spec.compat`, so the [DR-022](specs/decisions/022-runtime-compatibility-contract.md) skew check compared that engine with itself; they now declare the literal ABI current at link time, per [slc/link.md](slc/link.md), with no behavioral change under any shipped configuration. The five linker-modeled test fixtures carry the same literal, and the Captain constructs its factory on first use, so a future compat mismatch surfaces as the CLI's setup diagnostic instead of an uncaught module-load error.

- **A headless or managed turn that parks at a player question no longer fails settlement.** The shell mirrored the leaf's pending Boss question straight from state telemetry, whose full-context entry carries runtime-internal fields such as the resume state; the durable snapshot's leaf-projection equality then failed on the extra members, `exportSnapshot()` returned nothing, and the turn exited 2 with the question withheld and the turn's progress discarded to the pre-turn uncertain marker. The shell now mirrors only the specified `{ questionId, asker, question, sourceItem }` projection, so a parked-at-question turn settles durably and releases the question as the reply ([[playbook-captain-41](specs/packages/playbook-captain.md#playbook-captain-41)]).

- **A CODE run that REVIEW did not approve is no longer announced as a clean success.** CODE compiled exact approval, an authored REVIEW abort or failure, and a terminal REVIEW result that does not prove approval onto one `done` state described as completion after REVIEW found no unsettled findings. A host can quote only the runtime-published state description, so dismissing a parked nested review reported "completed after REVIEW found no unsettled findings" while the run output carried `review-failed`. Those authored failures now settle in their own terminal state naming the failure, and `done` is entered only by an exact approval ([DR-035](specs/decisions/035-truthful-terminal-meaning.md), [IR-043](specs/intents/043-truthful-terminal-meaning.md), [[playbook-27](specs/packages/playbook.md#playbook-27)]).

## [8.0.0] - 2026-08-17

### Added

- **Interactive and headless commands now create and reopen the same durable Captain session.** A managed interactive pane child owns the session lease, persists a complete turn-zero boundary before input opens, writes each turn uncertain before effects, and settles before releasing its reply. The public UUID reported by either front end reopens through either `playbook --session <id>` or `playbook run --session <id>`, retaining the Captain conversation, engagement stack, stable-player ledger, stored working directory, and exact settled boundary across presentation changes ([IR-042](specs/intents/042-explicit-roles-session-players.md), [[playbook-cli-49](specs/packages/playbook-cli.md#playbook-cli-49)], [[playbook-cli-50](specs/packages/playbook-cli.md#playbook-cli-50)]).

### Changed

- **Breaking: playbook-local roles now bind explicitly to stable Captain-session players.** Workflow artifacts declare semantic roles without host identity; the flat top-level `players` map declares provider agents, and each `playbooks.<id>.roles` entry names the exact player that owns its conversation. Equal player IDs deliberately share continuity across nested and later root engagements, distinct IDs remain isolated even with identical settings, and concurrent roles must name distinct players. Artifact schema 2 and trace, runtime-snapshot, shell-snapshot, and durable-record schema 3 preserve role and player identity separately and reject legacy schemas before effects ([DR-032](specs/decisions/032-explicit-roles-session-players.md), [IR-042](specs/intents/042-explicit-roles-session-players.md)).

- **Ordinary continuation can apply compatible current model and effort selections without losing provider continuity.** Each Captain and player call receives complete settings, including an explicit provider-default reset, while stored catalog membership, role bindings, adapter, instruction, permissions, and working directory remain fixed. A settings rejection retains the prior token instead of falling back fresh, and uncertain retry keeps its byte-exact input and attempted settings regardless of current config ([DR-032](specs/decisions/032-explicit-roles-session-players.md), [[playbook-cli-22](specs/packages/playbook-cli.md#playbook-cli-22)], [[playbook-cli-23](specs/packages/playbook-cli.md#playbook-cli-23)]).

- **The required `@sublang/cligent` range rises from `^0.19.0` to `^0.22.0`.** The new floor supplies segmented player ids, complete per-call settings and typed rejection, empty-roster sessions, managed attachment with abort-safe native-client hand-off and explicit work-directory cleanup authority, and reliable attached-client resizing; the final registry artifact is pinned by its exact integrity and verified through an override-free frozen install ([[release-14](specs/packages/release.md#release-14)]).

### Removed

- **Breaking: the standalone Sketch view is retired.** `views/sketch`, its CI job, and its spec package are removed; runtime `playbook.trace` remains the durable machine telemetry for host-native visualization ([DR-033](specs/decisions/033-sketch-view-retirement.md)).

- **Breaking: per-playbook `players` blocks and implicit same-role inheritance are removed.** Move agent definitions to top-level `players`, choose stable IDs, and bind every required role under `playbooks.<id>.roles`. This shape is deliberately not auto-migrated: choosing equal versus distinct IDs decides conversation sharing versus isolation, which the launcher cannot infer safely ([[playbook-cli-4](specs/packages/playbook-cli.md#playbook-cli-4)], [[playbook-cli-33](specs/packages/playbook-cli.md#playbook-cli-33)]).

- **Breaking: runtime-option builders and host-player helper types are no longer public registry or Captain exports.** `createCodeRuntimeOptions`, `createReviewRuntimeOptions`, `createDecideRuntimeOptions`, their `Create*RuntimeOptions` and `RegistryPlayer` types, `CreatePlaybookRuntimeOptions`, `defaultResolvePlayerId`, and `PlayerBridgeSpec` are removed; `XStatePlayerStateStatus` is replaced by role-oriented `XStateRoleStateStatus` ([[release-20](specs/packages/release.md#release-20)]).

### Fixed

- **Managed interactive launch now preserves Cligent's explicit cleanup authority across the private pane-child boundary.** The descriptor carries the launcher-issued boolean unchanged to the direct runner instead of guessing from a private marker, so Cligent 0.22.0 can remove only the work directory its launcher owns and retain every caller-owned directory ([[playbook-cli-49](specs/packages/playbook-cli.md#playbook-cli-49)], [[playbook-cli-50](specs/packages/playbook-cli.md#playbook-cli-50)]).

- **Kimi and OpenCode captains now use the same documented prompt-level tool-isolation fallback as Codex.** Their published Cligent adapters reject every explicit tool list, including the empty list used for control calls, so Playbook omits that unsupported option while retaining hidden-control prompts; Claude and Gemini continue to receive provider-enforced empty allowlists, and non-empty runtime-requested restrictions still fail closed ([DR-013](specs/decisions/013-routing-only-captain-control.md) A1, [[playbook-captain-31](specs/packages/playbook-captain.md#playbook-captain-31)], [[playbook-captain-33](specs/packages/playbook-captain.md#playbook-captain-33)]).

- **Implicit continuation now isolates released legacy session records instead of letting one block every current session.** `playbook run --continue` warns with each schema-2 record's id and path, skips only those authenticated legacy records, and still selects the latest schema-3 session; explicit legacy selection and malformed or unknown records continue to fail closed ([[playbook-cli-22](specs/packages/playbook-cli.md#playbook-cli-22)], [[playbook-cli-23](specs/packages/playbook-cli.md#playbook-cli-23)], [[playbook-cli-24](specs/packages/playbook-cli.md#playbook-cli-24)]).

## [7.0.0] - 2026-08-11

### Added

- **Complete headless Captain sessions can continue safely across processes.** Every settled `playbook run` turn is durably handed off before stdout with the compiled Captain conversation, engagement stack, mapped-player continuity, frozen execution config, working directory, and nested parked state intact. `--continue` selects the latest session and `--session <id>` selects one explicitly; exclusive leases and pre-effect uncertain markers reject competing writers and require explicit `--retry-uncertain` or `--discard-uncertain` recovery after interruption ([IR-041](specs/intents/041-shared-captain-session.md), [[playbook-cli-22](specs/packages/playbook-cli.md#playbook-cli-22)], [[playbook-cli-23](specs/packages/playbook-cli.md#playbook-cli-23)]).

### Changed

- **Breaking: `playbook run [input]` is now the tmux-free front end to the same Captain session engine as `playbook`.** Exact argument or verbatim stdin input enters one Boss turn over the same normalized shared config, compiled Captain, enabled catalog, nested stack, mapped players, provisioning, and readiness; plain stdout is exactly Captain's reply, while `--json` emits only `{ "sessionId": "…", "reply": "…" }` and operational output stays on stderr ([DR-031](specs/decisions/031-shared-captain-session-front-ends.md), [[playbook-cli-18](specs/packages/playbook-cli.md#playbook-cli-18)], [[playbook-cli-20](specs/packages/playbook-cli.md#playbook-cli-20)], [[playbook-cli-46](specs/packages/playbook-cli.md#playbook-cli-46)]).

### Removed

- **Breaking: the direct-registry run surface and separate run configuration are retired.** Positional `<from>`, `resume <id>`, `--player`, `--captain`, `--option`, `--cwd`, `--last`, run-only `--config`, and top-level `run:` no longer select or configure execution. Enable each registry under shared `playbooks`, invoke its effective `/command` through Captain, keep lineup and options under top-level `captain` and `playbooks.<id>`, use `--with` only for a new-session overlay, and replace old resume forms with `--session` or `--continue`; released direct-run snapshot records are not continuable ([[playbook-cli-19](specs/packages/playbook-cli.md#playbook-cli-19)], [[playbook-cli-22](specs/packages/playbook-cli.md#playbook-cli-22)], [[playbook-cli-28](specs/packages/playbook-cli.md#playbook-cli-28)]).

### Fixed

- **Completed root playbooks now give Captain their published final meaning before the shell disposes them.** Headless and interactive closing replies can report what an immediately terminal REVIEW, CODE, or custom workflow actually accomplished instead of saying only that it started; the shell retains one escaped and bounded runtime-authored state description as settlement evidence while opaque runtime output remains excluded ([[playbook-captain-20](specs/packages/playbook-captain.md#playbook-captain-20)], [[captain-playbook-10](specs/packages/captain-playbook.md#captain-playbook-10)]).

- **Restoring a parent parked behind a nested playbook no longer reopens or loses its child call.** Runtime snapshot schema 2 preserves exact suspended-call identity; restore reconnects the existing child without another host call or start trace and resumes the parent exactly once from the original child result, while ordinary schema-1 snapshots remain compatible ([[playbook-runtime-42](specs/packages/playbook-runtime.md#playbook-runtime-42)], [[playbook-runtime-45](specs/packages/playbook-runtime.md#playbook-runtime-45)], [[playbook-captain-42](specs/packages/playbook-captain.md#playbook-captain-42)]).

## [6.0.0] - 2026-08-11

### Added

- **REVIEW and DECIDE are bundled compiled playbooks.**
  REVIEW provides the committed-work review loop as both a standalone workflow and a child of other playbooks, while DECIDE obtains independent Coder and Reviewer proposals before committing a design and delegating its review; both ship maintained sources, GEARS, FSM, linked-runtime, and public playbook and registry subpaths ([[playbook-21](specs/packages/playbook.md#playbook-21)], [[playbook-22](specs/packages/playbook.md#playbook-22)], [[release-20](specs/packages/release.md#release-20)]).

- **Hosts can preserve a mapped player's conversation across composed runtimes.**
  The public runtime contract adds optional `PlaybookSession.playerSessions` and the synchronous `PlayerSessionStore`, letting nested exact same-role frames use a root-owned continuation while standalone runtimes retain private session state ([[playbook-runtime-58](specs/packages/playbook-runtime.md#playbook-runtime-58)], [[playbook-captain-10](specs/packages/playbook-captain.md#playbook-captain-10)]).

- **A deterministic Source-to-GEARS guard now protects maintained workflows.**
  The public SLC contracts and repository check preserve recognized authored prompt fragments, their order, and explicit quote markers, while checking that linked ownership agrees with GEARS-declared verbatim fields without attempting an agentic recompile ([[playbook-5](specs/packages/playbook.md#playbook-5)], [[playbook-6](specs/packages/playbook.md#playbook-6)], [[playbook-11](specs/packages/playbook.md#playbook-11)], [[release-28](specs/packages/release.md#release-28)]).

### Changed

- **CODE delegates every committed phase to REVIEW.**
  CODE owns each direct or intent-record phase commit and cannot advance until REVIEW approves the latest committed work with no unsettled findings ([[playbook-20](specs/packages/playbook.md#playbook-20)], [[playbook-21](specs/packages/playbook.md#playbook-21)]).

- **Factory-backed workflows use a metadata-derived human status profile.**
  The public XState runtime adds `XStatePlayerStateStatus` and `playerStates`, so CODE and REVIEW report exact guards and player labels instead of raw state-id fallback lines while metadata-absent schema-1 artifacts preserve their legacy status behavior ([[playbook-runtime-3](specs/packages/playbook-runtime.md#playbook-runtime-3)], [[playbook-runtime-57](specs/packages/playbook-runtime.md#playbook-runtime-57)]).

- **Canonical specs now use one package-only layout.**
  The former `specs/user`, `specs/dev`, `specs/test`, and `specs/iterations` trees are consolidated under `specs/packages` and `specs/intents`, and `pnpm test` now runs Spex lint with the `@sublang/spex` floor raised to 2.1.1 ([[meta-1](specs/meta.md#meta-1)], [[release-22](specs/packages/release.md#release-22)]).

### Removed

- **Breaking: DISCUSS and its public playbook and registry subpaths are replaced by REVIEW and DECIDE.**
  Call REVIEW for iterative committed-work review and DECIDE for independent design proposals followed by REVIEW; the `discuss` command and `@sublang/playbook/discuss/{playbook,registry}` imports no longer exist ([[release-20](specs/packages/release.md#release-20)]).

- **Breaking: CODE's embedded Reviewer and Committer selection are retired.**
  Existing configs must keep `playbooks.code.players.coder`, remove `playbooks.code.committer`, and enable REVIEW separately with `coder` and `reviewer`, while direct runtime consumers must stop supplying `reviewerPlayer` and `committerPlayer`; CODE now delegates committed phases to REVIEW and shares its Coder conversation by exact role id ([[playbook-cli-11](specs/packages/playbook-cli.md#playbook-cli-11)], [[playbook-20](specs/packages/playbook.md#playbook-20)]).

### Fixed

- **CODE and DECIDE retain exact commit identity across REVIEW.**
  Successful CODE phases and authored or invalid nested-REVIEW terminal outcomes return the latest CODE-owned commit, while DECIDE validates and retains the Coder's exact commit marker before REVIEW and returns it if an authored or invalid REVIEW outcome terminates; raw nested-call control errors park recoverably instead of masquerading as authored outcomes ([[playbook-20](specs/packages/playbook.md#playbook-20)], [[playbook-24](specs/packages/playbook.md#playbook-24)], [[playbook-25](specs/packages/playbook.md#playbook-25)]).

- **SLC no longer confuses typed relay values with verbatim player output.**
  Result ownership is derived from the authored contract, so typed fields such as intent numbers remain judge-authored while fields declared as verbatim final text remain player-authored through later prompt composition ([[playbook-5](specs/packages/playbook.md#playbook-5)], [[playbook-6](specs/packages/playbook.md#playbook-6)]).

## [5.0.0] - 2026-08-09

### Added

- **A broken markdown cross-reference now fails the suite.** `pnpm test` resolves every relative link in `specs/`, `CHANGELOG.md`, and `README.md`: the target file must exist, and any `#` fragment must match an anchor the target actually renders. Anchors are derived exactly as GitHub derives them, which is the part that matters — a character dropped from between two spaces leaves both spaces behind, so `### 11. Host adapter — tmux-play` answers only to `#11-host-adapter--tmux-play` with two hyphens, and any derivation that collapses repeated hyphens accepts the broken single-hyphen spelling silently; a near miss of that shape is reported with the spelling that would have worked. File existence alone is not enough either: the link that prompted this resolved to a file that *did* exist, in the wrong spec group, and only the anchor check caught it. Duplicate slugs take `-1` / `-2` suffixes, explicit HTML `id` / `name` anchors resolve, and reference definitions are checked like inline links, while text inside a fenced code block or an inline code span is not treated as a link at all — so a document may quote link syntax as prose, as DR-018 and `meta.md` both do. A target that resolves outside the project directory is a failure rather than a pass, so a link that only worked because a sibling checkout happened to sit beside this one can no longer ship — two links into `../../../cligent/` did exactly that and are now repointed at cligent's published URL, the form DR-004, DR-009, and DR-027 already use. The check also runs standalone as `pnpm check:links` ([IR-037](specs/intents/037-markdown-cross-reference-check.md), [[cross-references-1](specs/packages/cross-references.md#cross-references-1)], [[cross-references-2](specs/packages/cross-references.md#cross-references-2)], [[cross-references-3](specs/packages/cross-references.md#cross-references-3)], [[cross-references-4](specs/packages/cross-references.md#cross-references-4)]).

- **The engine owns a control surface: every shared-factory runtime now describes itself and applies advertised actions.** Runtimes built by `createXStatePlaybookRuntime` implement the optional `describe`/`apply` pair of `@sublang/playbook/runtime` (declared both-or-neither, feature-detected like the parked-session snapshot capability — no ABI or schema bump). `describe()` is a side-effect-free ControlView over the live snapshot: normalized state, the context projection the runtime itself authors — the FSM context members that artifact names and nothing else, so a member is private until named and a member added to an FSM later stays private — pending Boss questions with ids, the last recorded error, and the currently valid actions — a failure-state retry that replays the recorded last classified event with its recorded payload, and resumable-state jumps sent as the FSM's explicit-state-jump event with textual fields omitted, each labeled from source state descriptions and validated against live guards; a candidate whose payload cannot be sourced from recorded state is excluded rather than completed with invented text. `apply({ actionId, key, signal })` revalidates against the live state (`rejected` before any effect), executes at most once per idempotency key with the receipt recorded at acceptance — a repeated key returns the recorded receipt without re-execution, while a key that never reached acceptance (a thrown call or a `rejected` revalidation) records nothing and may execute later — and settles `executed` with the run result or `failed` with the normalized error after effects may exist. Past acceptance an effect failure becomes a `failed` receipt rather than a thrown ambiguity; once the finish receipt is published, a later telemetry-delivery failure leaves that receipt final and surfaces on the runtime emission-failure channel. Apply boundaries trace as paired schema-2 `apply.started`/`apply.finished` events carrying action id, key, and receipt disposition ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [IR-036](specs/intents/036-session-scoped-conversational-captain.md), [[playbook-runtime-5](specs/packages/playbook-runtime.md#playbook-runtime-5)], [[playbook-runtime-34](specs/packages/playbook-runtime.md#playbook-runtime-34)], [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).

- **`pnpm smoke:release` verifies a release candidate without a single model call.** Maintainers of this repository get one command — it ships in the repository, not in the published package — that packs the candidate with `npm pack` and drives eight steps against that tarball inside one isolated temporary root, stopping at the first failure and preserving the root so it can be inspected: the lean global install carries the nested cligent and no SDK directories; the opted-in install carries both agent SDKs as top-level roots; the installed `playbook --help` and `--list` name `code` and `discuss`; a bare-repo hermetic run provisions the engine once and provisions nothing on a second run; the packed compiled artifacts hash-equal the committed ones and their conformance suites rerun green; and the nested installed cligent satisfies the documented floor and really carries `CaptainContext.emitReply` and `CaptainRunResult.resumeToken` — each proven a member of its own interface by type-checking a fixture that uses it at the type the shell uses it at, resolved through the same `@sublang/cligent/tmux-play` specifier the shell imports. Looking for the two names instead cannot fail here: `resumeToken` names members of four unrelated cligent declarations and `emitReply` survives in a neighboring record type's doc comment, so a text scan stays green with both members deleted from the interfaces the shell calls. It spends no credential and creates no tmux session, but it does need npm registry access, because two of its steps install from it. It claims GEARS↔FSM↔runtime fidelity only — the SLC pipeline is agentic, so nothing here re-derives an artifact from its markdown source, and no suite reads the maintained `reference/sdlc/captain.md`. The pre-release ordering is now `pnpm test` → `pnpm smoke:release` → `pnpm test:acceptance` → the conditional manual UX smoke, and the opt-in live acceptance suite grows from four scenarios to five, the fifth exercising the conversational Captain end to end against real agents ([IR-036](specs/intents/036-session-scoped-conversational-captain.md), [[release-10](specs/packages/release.md#release-10)], [[release-24](specs/packages/release.md#release-24)], [[release-28](specs/packages/release.md#release-28)], [[release-25](specs/packages/release.md#release-25)], [[release-29](specs/packages/release.md#release-29)]).

### Changed

- **The Playbook Captain shell becomes a controller host: one session Captain, one durable conversation, and host-validated actions.** The compiled default Captain is now constructed at `init` with its own playbook session id and the host controller port, lives outside the engagement stack for the whole shell session, and receives every Boss turn — the lazily constructed internal root, the hidden deliver-or-dismiss lifecycle classifier, and the ask-first refusal of a second registered command are all retired. Registered commands resolve deterministically before any model call (idle `/cmd text` starts, `/cmd text` at the leaf delivers, an enabled command absent from the active path switches, a bare command or one naming an active non-leaf ancestor answers only), and the resolution reaches the runtime as the linker-exposed controller port's `resolveParsedTurn`, so `handleBossInput` keeps exactly `{ text, signal }`. Everything else settles through one hidden durable decision call whose validated `respond` | `start` | `switch` | `dismiss` | `deliver` | `runtime` selection returns to the shell for validation and execution: registry membership, an idle shell for `start`, an active root and an off-path target for `switch`, an active leaf for `dismiss` / `deliver` / `runtime`, and the leaf's own `describe()` advertising the action id for `runtime` — an invalid selection settles `rejected` with a reason and no effect, then follows the normal result-phase reply path. Delivered text is shell-authoritative (the exact Boss text, or a same-command turn's parsed remainder). A `start` / `switch` carries one nonempty standalone request — the exact command remainder for a parsed turn or a faithful consolidation of the request agreed across conversational turns — and a settlement with status `ok` is final for the turn. Captain prose reaches Boss only as validated captain speech through cligent `CaptainContext.emitReply`; `emitStatus` carries none. The acting turn's closing reply is composed by the session Captain from the settlement's outcome report — the facts verbatim, the receipt disposition and its normalized error, the leaf-state summary, and the exact counts — and the `summaryPolicy` saved-counts line is supplied for it only when the turn's counted activity is nonzero, so `Saved you 0 …` can no longer follow a turn that saved nothing ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [IR-036](specs/intents/036-session-scoped-conversational-captain.md), [[playbook-captain-1](specs/packages/playbook-captain.md#playbook-captain-1)], [[playbook-captain-2](specs/packages/playbook-captain.md#playbook-captain-2)], [[playbook-captain-19](specs/packages/playbook-captain.md#playbook-captain-19)], [[playbook-captain-7](specs/packages/playbook-captain.md#playbook-captain-7)], [[playbook-captain-8](specs/packages/playbook-captain.md#playbook-captain-8)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-captain-16](specs/packages/playbook-captain.md#playbook-captain-16)], [[playbook-captain-20](specs/packages/playbook-captain.md#playbook-captain-20)], [[playbook-captain-13](specs/packages/playbook-captain.md#playbook-captain-13)], [[playbook-captain-21](specs/packages/playbook-captain.md#playbook-captain-21)], [[playbook-captain-37](specs/packages/playbook-captain.md#playbook-captain-37)], [[playbook-captain-38](specs/packages/playbook-captain.md#playbook-captain-38)]).

- **Breaking: constructing the default Captain runtime now requires a controller port.** `PlaybookRuntimeOptions.controller` is required because every Boss turn settles through that host boundary; consumers that previously called `createPlaybookRuntime({ enabledPlaybooks })` must also supply the controller. Untyped JavaScript still receives the named fail-fast error on the first Boss turn rather than a silent failure ([[captain-playbook-9](specs/packages/captain-playbook.md#captain-playbook-9)], [[release-20](specs/packages/release.md#release-20)]).

- **The session Captain's conversation is durable, and a broken one is replaced instead of lost.** Every session-Captain call — the decision call, a parse-resolved command reply, and the acting turn's closing reply — runs hidden on one conversation whose returned `resumeToken` the shell pins in place of the prior pin, while interleaved sub-runtime judge calls stay fresh and never touch that pin. A call that throws, returns non-`ok`, or returns `ok` without a token marks the conversation unsynchronized: the pin is cleared and that one call is re-issued exactly once on a fresh conversation seeded with the shell's own deterministic reseed digest of the session journal plus the current ControlView digest — never a reseed plus another retry — and only the model-side conversation is replaced, so the engagement stack, player sessions, journal, and the turn's already-executed work all survive. A rejected Captain-speech presentation is never retried, but it likewise forces the next call onto a fresh recap containing the exact attempted prose and its uncertain delivery, so the new conversation can understand either kind of Boss follow-up without claiming the display succeeded. The journal itself is host-kept, append-only, JSON-safe, never Boss-visible, and exists only for that reseed; a raw journal record reaches no prompt. A second consecutive continuity failure fails the phase with a Boss-appropriate reply naming a concrete next step, the stack untouched and the raw diagnostic left on trace telemetry ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [[playbook-captain-31](specs/packages/playbook-captain.md#playbook-captain-31)], [[playbook-captain-35](specs/packages/playbook-captain.md#playbook-captain-35)], [[playbook-captain-34](specs/packages/playbook-captain.md#playbook-captain-34)], [[playbook-captain-39](specs/packages/playbook-captain.md#playbook-captain-39)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)]).

- **Raise the registry dependency closure to cligent 0.19.** `@sublang/cligent` moves from `^0.18.0` to `^0.19.0`, and the lockfile pins the published `0.19.0` with its registry integrity hash, because the controller shell consumes two surfaces 0.18 does not ship. `CaptainRunResult.resumeToken` is the durable Captain conversation's pin: the shell replaces the prior pin after every session-Captain call, and its absence is one condition that marks a conversation unsynchronized and triggers the single journal-seeded reseed. `CaptainContext.emitReply` is the captain-speech surface: the explicit `captain_reply` channel that renders validated Captain prose as ordinary Captain speech rather than as a bracketed `emitStatus` line, which is the only path controller prose has to Boss now that every decision and closing-reply call runs hidden. The bump was held until 0.19.0 published — a committed manifest whose range no committed resolution satisfies is what [[release-19](specs/packages/release.md#release-19)] rejects on behalf of [[release-14](specs/packages/release.md#release-14)] — so the range and the lockfile move together here, with the git-ignored [[release-11](specs/packages/release.md#release-11)] local-development override removed first so the regenerated lockfile records the registry resolution and no `link:` anywhere. This closes the [IR-036](specs/intents/036-session-scoped-conversational-captain.md) landing unit and turns [[release-28](specs/packages/release.md#release-28)]'s nested-cligent floor guard green, so the opt-in live acceptance suite now drives a candidate whose installed cligent carries both surfaces ([[release-4](specs/packages/release.md#release-4)], [[release-12](specs/packages/release.md#release-12)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-captain-31](specs/packages/playbook-captain.md#playbook-captain-31)]).

- **The default Captain playbook is recompiled to the session-scoped controller.** The rewritten `reference/sdlc/captain.md` compiles through the SLC pipeline into new `reference/sdlc/captain.playbook/` GEARS, FSM, and linked-runtime artifacts. The machine is a session loop, not a finite errand: a parked conversational hub receives every Boss turn; one decision per turn selects from the closed action set `respond` | `start` | `switch` | `dismiss` | `deliver` | `runtime` (the stable controller guard contract); an acting selection's controller-port settlement grounds one closing-reply call; and the machine returns to the hub — with exactly one `type: 'final'` shutdown state entered only by the host's teardown event, no terminal `{ response }` output, no nested `callPlaybook`, and no Boss-reply suspension (a clarifying question to Boss is a `respond` selection). The linked module becomes a thin artifact over the shared `createXStatePlaybookRuntime` factory with a `spec.compat` declaration: the host-supplied controller port rides the linked options, every decision and closing-reply call runs `{ visibility: 'hidden' }` with the decision reply validated as `{ action, … }` control JSON under exactly one corrective re-ask (a second malformed reply settles the turn back at the hub with no action executed), a parse-resolved turn enters with its injected decision object and no decision call, and Boss turns map deterministically from the host's command-parse resolution with no classifier judge call. The compiler contracts land alongside: `slc/gears2fsm.md` §Setup gains the additive controller decision-state class, `slc/link.md` gains the controller Captain-call presentation and the rewritten §Boss-event mapping entries, the engine gains the additive controller spec seams (`captainStrategy`, hidden-call trace form, an options-aware classifier), and the regenerated `.slc-verify` bundle and suites pin the new source–FSM–artifact agreement including the six CAPPLAY-20 prompt-contract re-pins ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [IR-036](specs/intents/036-session-scoped-conversational-captain.md), [[captain-playbook-6](specs/packages/captain-playbook.md#captain-playbook-6)], [[captain-playbook-16](specs/packages/captain-playbook.md#captain-playbook-16)], [[captain-playbook-18](specs/packages/captain-playbook.md#captain-playbook-18)], [[captain-playbook-11](specs/packages/captain-playbook.md#captain-playbook-11)], [[captain-playbook-19](specs/packages/captain-playbook.md#captain-playbook-19)], [[captain-playbook-20](specs/packages/captain-playbook.md#captain-playbook-20)]).

### Fixed

- **A host failure before an effect is no longer reported as an effect failure.** Visibility, telemetry, validation, runtime invocation, and result processing are attributed at the operation that actually fails. The Captain therefore reports the facts it can establish without pretending an unstarted effect ran; a rejecting presentation boundary is surfaced once rather than retried through another channel ([[playbook-captain-35](specs/packages/playbook-captain.md#playbook-captain-35)], [[playbook-captain-39](specs/packages/playbook-captain.md#playbook-captain-39)]).
- **The shared XState runtime now rejects parallel FSMs at construction.** The shared factory is the single-region engine defined by DR-019; accepting a machine that happened to expose only one `meta.playbook` state id let an unsupported parallel snapshot initialize and publish one region's description as if it described the whole state. The linker now keeps parallel playbooks such as DISCUSS on their bespoke output profile instead of emitting a partially compatible thin runtime ([DR-019](specs/decisions/019-shared-linked-runtime-factory.md), [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).
- **Selection identifiers are guarded without rejecting Boss-facing prose.** Advertised action ids, pending-question ids, and action ids replayed by a recovery recap enter the reply guard from their typed fields; labels, questions, player names, catalog prose, handoffs, and result facts remain speakable even when they resemble an id. The match is token-aware and has no length floor, so `q1` and `5` are guarded without treating the `5` inside `1.5.2` as a repeat. Live UUID checks also compare hexadecimal case-insensitively, so uppercasing a session id cannot expose it ([[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)]).
- **No field a runtime or a registry publishes can forge a block in the Captain prompt.** The shell frames foreign content in labeled blocks, and escaping was applied field by field: the context lines and the pending questions went through the bounding-and-escaping seam while the advertised action's id and label and the enabled playbook's intent — three plain strings in the same function — were interpolated raw. A newline in any of them opened a second `[Boss message]` or `[Catalog digest]` inside the composed prompt, the forged instruction reading to the model as host-authored and the forged catalog sitting above the real one. Every foreign value now becomes part of a digest line through one seam, so a line added later carries the property without restating it ([[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)]).
- **Every selected Captain action now returns through one conversational result path.** Success, host or runtime rejection, failure, and partial completion all return their recorded facts to the same durable Captain conversation before its grounded reply. The separate refusal status, refusal journal kind, and next-turn refusal notice are gone, so the Captain cannot remember choosing an action without learning how it ended. Operational failures are recorded conservatively and never cause the action to run again; if reply presentation rejects, the shell makes no second presentation attempt and surfaces the boundary failure ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [[playbook-captain-34](specs/packages/playbook-captain.md#playbook-captain-34)], [[playbook-captain-35](specs/packages/playbook-captain.md#playbook-captain-35)], [[playbook-captain-39](specs/packages/playbook-captain.md#playbook-captain-39)]).
- **Conversational starts and switches now hand off the complete agreed task.** The Captain may combine remembered Boss requirements with the current turn into one standalone request for the selected playbook, while deterministic slash commands continue to pass their exact parsed remainder. This replaces the origin-tagged input split that could carry either earlier intent or the current turn but not both ([DR-029](specs/decisions/029-session-scoped-conversational-captain.md), [[playbook-captain-7](specs/packages/playbook-captain.md#playbook-captain-7)], [[captain-playbook-9](specs/packages/captain-playbook.md#captain-playbook-9)]).
- **An advertised action id can no longer reach the Boss through the reply that names it.** The digest hands the model complete action ids so it can select one, but those ids are not Boss-facing prose. Runtime action labels now come from authored descriptions, and validated Captain replies reject machine-shaped identifiers supplied by the host without rejecting ordinary words such as `ready` or `failed` ([[captain-playbook-5](specs/packages/captain-playbook.md#captain-playbook-5)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).
- **The public-API release gate now sees type-only exports.** The gate added to stop a second accidental breaking removal compared one recorded set of names against both the JavaScript module and its declaration file, which forced its declaration scan to match only the forms the JavaScript also carries — `export declare function|const|class|let|var` — and so left roughly forty exported interfaces, type aliases, and `export type { … }` re-exports unpinned, `CaptainControllerPort` among them, which is the type of `PlaybookRuntimeOptions.controller` that every host must implement to construct the runtime. The two sets are now recorded separately, the declaration scan covers every export form, and the scan itself is proven falsifiable by removing one export of each form. Which subpaths are pinned is derived from `package.json`'s `exports` map minus one recorded exclusion rather than listed, so a subpath added to the manifest goes red until it is recorded — a list left `./xstate-runtime`, `./code/playbook`, `./playbook-captain`, and `./discuss/playbook` unpinned, and adding one name would have left the next. A wildcard re-export naming a relative in-package target is resolved and enumerated into that subpath's recorded set, in the `export *` form and the `export type *` form alike; one naming anything else fails, that being the case no enumeration can resolve. The type form is the one that matters in a declaration file, and a rejection written for the value form neither rejected nor enumerated it ([[release-20](specs/packages/release.md#release-20)], [[release-21](specs/packages/release.md#release-21)]).
- **Dropping a running playbook no longer repeats its last state line.** Dismissing an engagement, or switching away from one, showed the dropped playbook's current state twice — `◆ failed` immediately before `◇ /checklist stopped`, `⤷ outline` twice on a plain dismissal — because `dispose()` stopped the XState actor with inspection still live. Stopping a still-running actor makes XState emit one final snapshot carrying the *unchanged* state value with `status: 'stopped'`, and the runtime read it as a state entry: it re-ran the state's status composition and appended a phantom self-loop `fsm.transition` trace and `playbook.fsm.state` telemetry beside the visible duplicate, redundant with the `session.disposed` trace emitted immediately after. Disposal now suppresses inspection before stopping, as the failed-start and snapshot-restore paths already did, so a disposed runtime reports exactly one boundary — its own `session.disposed` — and any state it was parked in is announced once, when it was entered. A runtime that reached a final state was never affected: its actor had already run its stop procedure, so the stop was a no-op. The reference DISCUSS runtime keeps its own actor rather than the shared factory's, so it needed the same fix and did not inherit it; both it and the engine now stop through a single seam that suppresses first, and the suite discovers every runtime source that builds an actor and fails unless each has exactly one such site, so the next such artifact is covered by construction ([IR-036](specs/intents/036-session-scoped-conversational-captain.md), [[playbook-runtime-6](specs/packages/playbook-runtime.md#playbook-runtime-6)], [[playbook-runtime-22](specs/packages/playbook-runtime.md#playbook-runtime-22)]).
- **A dismissed engagement can no longer leave the shell reporting itself as engaged.** The shell selects `chat` before it unwinds the stack, and it disposes a frame before it pops it — so telemetry a runtime emitted on the way down still found itself the active leaf, and a parked state descriptor in that telemetry moved the authoritative mode straight back to `engaged.parked`, leaving an emptied stack reported as engaged in the control ledger with a leaf whose actor was stopped. The shell now mirrors only telemetry that is evidence about a live leaf: a payload whose actor status is not `active` is a teardown artifact, and a payload from a frame whose disposal has already begun belongs to an engagement that is going away. Both pass through to the host untouched and update neither the leaf ledger nor the mode. The guard is the shell's own and does not rest on any runtime's disposal hygiene, so it holds for a runtime the shell did not author ([[playbook-captain-10](specs/packages/playbook-captain.md#playbook-captain-10)], [[playbook-runtime-22](specs/packages/playbook-runtime.md#playbook-runtime-22)]).
- **A leaf's private FSM state no longer reaches the Captain conversation.** The ControlView exported every JSON-safe member of a runtime's FSM context, which for CODE meant the resolved player roster, option values, and raw player output reaching the durable Captain prompt. The view's context is now an explicit projection each runtime authors, and the shell renders each exported member as bounded, escaped evidence instead of inline JSON. A failing `describe()` is reported as an unreadable view rather than as an absent control surface ([[playbook-runtime-34](specs/packages/playbook-runtime.md#playbook-runtime-34)], [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)], [[playbook-captain-37](specs/packages/playbook-captain.md#playbook-captain-37)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)]).
- **A host call can no longer start after its turn was aborted.** Every traced call boundary — player, direct-Captain, and judge — now re-checks its combined signal between the awaited `*.call.started` emission and the host port invocation, so an abort that lands while that emission drains (for example, fired from the telemetry sink observing it) settles the already-started pair as `aborted` with no host call made; previously the boundary's pre-call checks could not see that window and the host call started anyway. The same window in the new `apply()` boundary settles before acceptance — no action execution, no receipt recorded, the idempotency key left free — with its `apply.finished` trace carrying the canonical rejected-before-any-effect receipt disposition required of every apply finish, and a finish sink rejecting that abort finish surfaces from the boundary in place of the abort, matching the settlement-drain precedence of the other public boundaries; a failure-state retry action is now labeled from the recorded `BOSS_INTERRUPT` event's own `targetId` rather than the first configured arm of a guarded transition list ([[playbook-runtime-13](specs/packages/playbook-runtime.md#playbook-runtime-13)], [[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-18](specs/packages/playbook-runtime.md#playbook-runtime-18)], [[playbook-runtime-51](specs/packages/playbook-runtime.md#playbook-runtime-51)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).
- **The Captain now speaks about a run's state in words instead of state ids.** The ControlView carries the runtime's Boss-facing state description, and the shell's digest uses that description rather than an internal id. A state with no published description remains undescribed instead of falling back to its id, while visible-prose validation remains narrow enough not to reject ordinary words such as `ready` or `failed` ([[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-34](specs/packages/playbook-runtime.md#playbook-runtime-34)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[captain-playbook-5](specs/packages/captain-playbook.md#captain-playbook-5)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)], [[playbook-captain-37](specs/packages/playbook-captain.md#playbook-captain-37)], [[playbook-captain-40](specs/packages/playbook-captain.md#playbook-captain-40)]).
- **A failed turn's reply is no longer forgotten by the next Captain.** Every Boss-visible Captain reply now leaves the shell through one seam that journals it, the host's own "I could not finish that turn" fallback included — it previously went straight to the Boss pane with no record, so a conversation replaced after a continuity failure saw the Boss's next message with no idea what the host had last said, and could read "okay, do that" as agreement to work that never ran. The same fallback is now Boss-facing in what it names: an executed or refused runtime action is named by the label its runtime advertised, never by the action id, and the composed reply passes the same prose validation every model reply passes — where the recorded facts quote runtime-authored text that fails it, the reply drops the facts and still states that the work ran and what to ask next, rather than printing unvalidated text ([[playbook-captain-34](specs/packages/playbook-captain.md#playbook-captain-34)], [[playbook-captain-9](specs/packages/playbook-captain.md#playbook-captain-9)], [[playbook-captain-35](specs/packages/playbook-captain.md#playbook-captain-35)], [[playbook-captain-39](specs/packages/playbook-captain.md#playbook-captain-39)]).
- **`apply()` no longer reports two different final dispositions for one action.** A rejecting `apply.finished` telemetry sink rewrote the already-emitted `executed` receipt to `failed` and destroyed the run result with it, so the caller was told that work which had succeeded had failed — irrecoverably, since accepted receipts are final for their key, and pointlessly, since the `executed` disposition was already on the wire and no rewrite could make the trace and the return agree. Publication is now an explicit line: a settlement failure before the finish emission still folds into the receipt (nothing has been published, so trace, return, and replay can still be made to agree), while one at or after it leaves the receipt alone and travels on the runtime's emission-failure channel to surface from the next public boundary that drains. A receipt states what happened to the effect; a telemetry sink going offline is not that ([[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).
- **The linker contract can regenerate the artifacts it is supposed to generate.** `slc/link.md` still described the ControlView context as a sanitized serialization of the FSM context — the allow-by-default behavior the projection replaced — carried no rule for authoring or emitting the projection at all, and closed §Output's emitted-spec list without it, so a linker following the document would have produced an artifact that either leaked the whole FSM context or exposed none of it, undoing the privacy fix on the next re-link. §Control surface now states the authored-projection contract and names `controlContextFields`; §Output lists it, states that its default is nothing rather than everything, and requires the `_internal` composers each machine actually uses instead of a fixed player-and-Captain pair the controller Captain cannot satisfy. The suite now checks those clauses are still stated where a linker would read them, and discovers every linked artifact in the repository to fail unless each declares its projection ([[playbook-runtime-52](specs/packages/playbook-runtime.md#playbook-runtime-52)], [[playbook-runtime-35](specs/packages/playbook-runtime.md#playbook-runtime-35)], [[playbook-runtime-53](specs/packages/playbook-runtime.md#playbook-runtime-53)]).
- **A transient empty agent reply no longer costs the whole turn.** cligent keeps `PlayerRunResult.finalText` optional, so any adapter may legally return `status: 'ok'` with no text; the engine previously failed the turn at once (`captainBridge: callPlayer returned status=ok with no finalText`), and its two call boundaries disagreed on whether `''` counted as empty. The delegated-player bridge and the direct-Captain boundary now treat a missing, empty, or whitespace-only `finalText` under one shared predicate and re-issue the same call exactly once — the corrective call traced as its own started/finished pair, a corrective player call continuing the player session under the stored resume selection — before a second such result follows the existing failure path unchanged. The linked DISCUSS reference runtime applies the same predicate and re-ask at its player boundary. Non-`ok` results, thrown calls, aborts, and rejecting finish-trace sinks are never retried ([DR-028](specs/decisions/028-empty-ok-result-re-ask.md), [IR-035](specs/intents/035-empty-ok-result-re-ask.md), [[playbook-runtime-9](specs/packages/playbook-runtime.md#playbook-runtime-9)], [[playbook-runtime-47](specs/packages/playbook-runtime.md#playbook-runtime-47)], [[playbook-runtime-23](specs/packages/playbook-runtime.md#playbook-runtime-23)], [[playbook-runtime-51](specs/packages/playbook-runtime.md#playbook-runtime-51)]).

### Added

A non-abort thrown port, a malformed host result, and a rejecting `captain.call.finished` sink remain control-plane errors that reject, and a rejecting finish sink still leaves the host result as the failure state's own evidence ([[playbook-runtime-47](specs/packages/playbook-runtime.md#playbook-runtime-47)], [[playbook-runtime-13](specs/packages/playbook-runtime.md#playbook-runtime-13)], [[playbook-runtime-41](specs/packages/playbook-runtime.md#playbook-runtime-41)]).
- **`slc/link.md` now names the Boss-event types a linker must never emit.** The `bossEvents` contract paragraph states that `NO_ACTION` and `BOSS_REPLY` are runtime-owned — the shared factory supplies `NO_ACTION` as exactly `{ type: 'NO_ACTION' }` and `BOSS_REPLY` as an optional judge-selected `questionId` plus the runtime-attached exact-text `answer` — so a linker that reads the erasure rule literally no longer emits a `BOSS_REPLY` entry that the factory rejects at construction, which would leave the emitted module dead on import ([DR-019](specs/decisions/019-shared-linked-runtime-factory.md), [IR-027](specs/intents/027-linked-runtime-boundary-fixes.md)).
- **Raise the registry dependency closure to cligent 0.16.** `@sublang/cligent` moves from `^0.15.0` to `^0.16.0`, and the lockfile pins `0.16.0`, whose tmux-play contract keeps the pre-close Captain lifecycle, explicit player resume, and isolated tool-restricted Captain calls the runtime requires ([[release-14](specs/packages/release.md#release-14)]).

### Fixed

- **A derived `BOSS_INTERRUPT` no longer drops the Boss's exact directive.** The shared factory derives that event's contract from the machine's root transition; it supplied the judge-selected `targetId` but not the runtime-owned `bossIntent` text field, so an FSM reading `event.bossIntent` on interrupt silently received `undefined` unless the linker also emitted explicit `bossEvents`. The derived contract now carries `bossIntent` — still runtime-attached, still withheld from the classifier prompt — and a derived contract sharing its type with the deterministic entry event merges with it rather than replacing it ([slc/link.md](slc/link.md), [IR-027](specs/intents/027-linked-runtime-boundary-fixes.md)).
- **Conflicting `bossEvents` metadata fails construction even with a custom classifier.** Supplying `classifyBossText` short-circuited the derived-contract build that is the only enforcement of the non-weakening merge rule, so a playbook with its own classifier could ship metadata contradicting the machine's own entry text ownership or closed interrupt targets undetected ([DR-019](specs/decisions/019-shared-linked-runtime-factory.md)).

## [0.4.0] - 2026-05-28

### Changed

- **Breaking:** `captain.options.coderPlayer` / `reviewerPlayer` are no longer required in the host configuration. The tmux-play adapter now derives the per-run player identity strings (substituted into `<coder-llm>` / `<reviewer-llm>` placeholders in player prompts) from `players[].adapter` at init time per PBRT-4, removing the duplication with the `players:` section. Stale `captain.options.coderPlayer` / `reviewerPlayer` keys in existing user configs are silently ignored; delete them at your convenience. The bundled template, dev config, production config, and `playbook-code --help` text no longer mention these keys.
- Captain-pane status stream redesigned per PBRT-3: glyph vocabulary shrinks to three (`⤷` state entry as `<Player>: <label>`, `→` guard outcome as `→ <guard>[ · field=N]`, `◆` failure/awaitBossReply only). The `◆ ready` and `◆ done` tombstones are no longer emitted — the next `boss>` prompt is the implicit turn-over signal. The Boss-input echo is replaced with a bare classification line carrying only the FSM event type (e.g., `START_CODING`), which the host renders as captain speech. State entries no longer carry the source-item tag (`CODE-N`) or the rider fields (`intent=…`, `irNumber=…`, `taskDescription=…`); the Boss readline already shows the verbatim Boss text. The runtime emits each line as bare content with no leading whitespace; speaker chrome (the current cligent `captain> [status] …` prefix) and any visual nesting under parent lines are presentation concerns and remain the host's responsibility.

### Fixed

- Player-prompt composer now arranges labelled blocks around the body based on the body's directional language: `Boss intent:` and `Task description:` stay above the body as prior context, while `Review items:` and `Rebuttals:` are appended below the body so the CODE-N prompts' "for each review item below" / "for each rebuttal below" phrasing matches the rendered layout. Previously every labelled block was prepended, contradicting the body's instructions. The continuation preamble + Q/A blocks still precede every ordinary block. PLAYBOOK-5 and DR-004 §6 updated.

## [0.3.0] - 2026-05-27

### Added

- `playbook-code` first-run onboarding (IR-011). Without `--config`, the shim resolves a user-level config at `${XDG_CONFIG_HOME:-$HOME/.config}/playbook/playbook-code.config.yaml`, seeds it from a bundled template if absent (with one stderr line naming the path), and launches against it instead of the in-package production yaml. A readiness gate inspects the declared `captain.adapter` and `players[].adapter` values and refuses to launch when a known adapter (`claude`, `codex`) lacks its API key or local CLI directory; unknown adapters emit a warning but don't block. `--help` / `-h` prints the resolved config path, per-adapter auth pointers, and the agent-swap recipe, then exits without seeding or launching. Specs: PBCODE-5..8.

### Changed

- **Breaking:** `playbook-code` and the CODE tmux-play configs now match cligent's player terminology: config key `roles:` is now `players:`, help/spec text names `players[].id`, and the adapter calls `CaptainContext.callPlayer(...)`. Requires `@sublang/cligent` ≥ 0.6.0 (the tmux-play role-to-player rename). Existing user configs must rename the top-level `roles:` key to `players:`; `players[].id` values stay `coder` and `reviewer` per PBRT-4.
- Captain prompts now cite `meta.md` so the Captain can ground its judgments in the spec-of-specs vocabulary.

## [0.2.0] - 2026-05-24

### Added

- Boss-reply suspension. Any captain-invoking state can now pause when the player surfaces a clarifying question for Boss: the FSM parks at `awaitBossReply` and the Captain pane shows the question; Boss's next turn is normally classified as the reply (a clearly fresh directive abandons the pending question instead), and the same state resumes with the Q+A in its prompt. DR-005 introduced the path, IR-006 implemented it, and IR-008 made it universal across every captain-invoking state.

### Changed

- **Boss turns are now plain language; the judge is the sole classifier.** Every non-empty Boss turn is passed to the judge, which classifies it into one of the FSM's events (or `NO_ACTION`); the judge picks `BOSS_INTERRUPT` targets from the FSM's jumpable states by their human-readable descriptions. There is no slash fast-path — text starting with `/` is treated as ordinary Boss content. (IR-009)
- Bundled `tmux-play` configs (dev and production) now set `permissions.mode: auto` on the captain and both roles, so each agent runs in cligent's protected auto mode (claude `permissionMode: 'auto'`, codex `on-request + auto_review`). Routine in-session approval prompts are suppressed.

### Removed

- The four slash commands `/start <intent>`, `/continue <#>`, `/summarize <#>`, and `/interrupt <stateId>` are no longer recognized by the runtime. Their behavior is now reached by typing the same intent in plain language (see Changed). The `/command` namespace is reserved for host-level playbook selection. (IR-009)
- Framework-injected "If a specific Boss answer is needed, ask the exact question and stop." player-prompt instruction. Boss-reply suspension still works: a clarifying question that naturally appears in player prose is detected by the adjudicator's `needsBossReply` classification — no nudge prompt is needed. (IR-010)

## [0.1.2] - 2026-05-17

### Fixed

- `playbook-code` after a global install (`npm install -g @sublang/playbook ...`) no longer fails with `ClaudeCodeAdapter requires @anthropic-ai/claude-agent-sdk`. v0.1.1 added the SDKs as dependencies, but global-install topology puts each top-level package in its own siloed `node_modules/` — so cligent (installed as a separate global package) couldn't walk up to find the SDKs sitting in `@sublang/playbook/node_modules/`. v0.1.2 moves `@sublang/cligent` into `dependencies` so it lands transitively inside playbook's tree; the SDK resolution walk now hits the deps. The single-command install is now `npm install -g @sublang/playbook` (cligent comes along).
- `bin/playbook-code` no longer requires `tmux-play` on `PATH`. The shim now resolves the CLI through `require.resolve('@sublang/cligent/tmux-play')` and execs it via `node`, so it works regardless of whether the user has cligent installed separately.

### Changed

- `engines.node` raised from `>=20` to `>=20.6.0`. The new `playbook-code` shim uses `import.meta.resolve` synchronously, unflagged only since Node 20.6.0; the previous declaration advertised Node 20.0–20.5 as supported but would crash there before `tmux-play` launched.
- CI's smoke job now uses a global-prefix install and probes adapter SDK resolution from cligent's installed location — the topology that surfaces the v0.1.1 regression. The previous local-style install hoisted everything into a shared `node_modules/`, masking the bug.

## [0.1.0] - 2026-05-17

### Added

- Three-phase playbook compiler stack as specs: `slc/text2gears.md` (prose → GEARS spec items, one per state behavior), `slc/gears2fsm.md` (GEARS → XState v5 finite state machine, one captain-invoking state per item), and `slc/link.md` (FSM → host-agnostic runtime driven by Boss turns through typed ports).
- Reference CODE playbook published as `@sublang/playbook` — a worked end-to-end example of the stack driving a coder / reviewer / committer loop. Source at `reference/sdlc/code.md`; compiled to gears `code.gears.md` (CODE-1..19), FSM `code.fsm.ts`, runtime `code.playbook.ts`, and `tmux-play` adapter `code.tmux-play.ts`.
- Captain-pane status stream with a four-glyph vocabulary (`◆` terminal/idle, `▸` Boss-input echo, `⮕` captain-invoking state entry with label + player + CODE-N + rider fields, `⤷` transition guard with payload tallies). Telemetry stream stays structured under topic `playbook.fsm.state`.
- `playbook-code` CLI bin — launches `tmux-play` with the bundled `tmux-play.production.config.yaml` so end users can run the reference playbook with one command after `npm install -g @sublang/playbook @sublang/cligent`.
- Conformance test suite (386 tests across six files) pinning the gears ↔ FSM 1:1 mapping (PLAYBOOK-1..6), runtime contract (PBRT-5..16), prompt composition, introspect helpers, and onDone arm coverage.
- Package exports `./code/playbook` (the host-agnostic `createPlaybookRuntime` factory) and `./code/tmux-play` (the cligent-bound Captain factory).
